# Workspace Rules

Whenever writing code (whether frontend UI, animations, or backend logic), always adhere to the following rules:

## 1. Design & UX Level
- **Aesthetic**: Premium, modern, and highly polished UI.
- **Details**: Smooth animations, proper spacing, well-curated color palettes, and subtle micro-interactions (hover effects, transitions, loading states).

## 2. Code Quality & Simplicity
- **Readable & Clean**: Keep the code short, clean, and beginner-to-intermediate friendly.
- **No Over-Engineering**: Avoid unnecessary abstractions or complex architecture unless strictly needed.
- **Naming**: Use clear, descriptive, and understandable variable/function names.
- **Formatting**: Avoid deeply nested code block structures and cryptic one-liners.
- **Inline Comments**: Provide a short, simple comment right above any complex line or block of logic to explain what it does.

## 3. Logical Structure
Organize files and components into clear, commented sections to make the flow easy to follow:
- `// State` - for state variables and hooks
- `// Handlers` - for event handlers, helper functions, and logic
- `// Render` - for UI rendering and return blocks

## 4. Explaining Advanced Concepts
- If advanced patterns or functions are necessary (e.g., `reduce`, custom hooks, memoization, aggregation pipelines), add a short explanation (2-3 lines) at the end of the code explaining **why** it was used.
